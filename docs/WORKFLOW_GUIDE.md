# `modtree` 实战使用流程与避坑指南

本文针对真实开发中最容易踩坑的 6 个场景，给出一套从空项目起步到合并收口的标准操作流程。

---

## 场景 1：空项目从 0 起步（先扁平建底座，别一开始就拆深层树）

**常见误区**：项目还是空的，就先硬拆 3 层子模块，并且第 1 分钟就同时给 A、B 开 Worktree 并行写——结果两边都建自己的 `package.json`、`App.tsx`、公共类型，最后合并满屏冲突。

**正确流程**：
1. 初始化 Git 仓库并做一次初始提交：
   ```powershell
   git init -b main
   git commit --allow-empty -m "init"
   ```
2. 打开右侧 Aux Pane → **`模块树`**。
3. **只建 3–5 个扁平一级模块**（或先建 1 个 **`项目底座`**，如：`项目底座`、`结果导出`、`图表展示`）。
   - 能不拆子模块就不拆！**子模块不是提前规划出来的，是写着写着发现某模块太大、单会话聊不动时再自然拆出来的。**
4. **单线先把「项目底座」做完并合进 `main`**：
   - 在主目录（**不要开 Worktree**）选中 `项目底座` → 点 **「开启会话」** → `Plan` 阶段聊清技术栈、目录骨架、路由入口与公共数据结构，让 Agent 写入 `设计要点`。
   - 点 **`Code`** 解锁编码，把脚手架、`package.json`、公共类型与主入口写完提交到 `main`，状态手动标为 **`已完成`**。

---

## 场景 2：日常开发节奏——`Code` 内子代理自测，不要频繁来回切 `Review`

**常见误区**：每改几行代码就切一次 `Review` 锁写权限 → 审出小问题又切回 `Code` → 修完再切 `Review`，来回点到怀疑人生。

**正确流程**：
1. **`Plan`（只读规划）**：明确目标、边界、接口契约与验收要点，沉淀进 `设计要点`（公共接口契约上提到父节点 `设计要点`）。
2. **`Code`（主力开发 + 自测闭环）**：
   - 在侧栏点 **`Code`** 解锁写入权限。
   - 日常迭代、小改动、修 bug 全留在 `Code` 里完成：写完一小段，直接跑测试，或者在当前 `Code` 会话里让 Agent **调用 Antigravity 原生只读子代理（如 `code-reviewer` / `research`）做自查，发现小问题当场修掉**。
   - 每轮工作结束，Agent 会自动调用 `modtree_update_progress` 更新「停在 / 下一步 / 关联文件」，你不需要手动填进度表。
3. **`Review`（仅在合并主干 / 大功能收口前做 1 次独立终审）**：
   - 平时根本不用碰 `Review`。
   - 等整个模块或父模块准备合并回 `main` 时，再切到 `Review` 点 **「开独立审查会话」**，基于 `git diff main...HEAD` 对照 `设计要点` 做一次干净的独立把关。
   - 如果真审出阻塞问题，Agent 会写入黄色 **`Review 返工问题清单`** → 点清单右上角一键 **「回 Code 修复」**（一步切回 `Code` 并跳回 Code 会话，下一轮发消息自动注入返工清单）→ 修完即可合并。

## 场景 3：同一模块里，一会儿想到改 a、一会儿想到改 b，怎么办？

**铁律：绝对不要把一次性修 bug 或小改动建成「子模块」**（比如不要建一个叫“修复中文乱码”的子模块，一周就会把树变成垃圾堆）。

分 3 种情况处理：
1. **正在写当前功能时顺手冒出的小点子**（10 分钟能顺带改完）：
   - 记在当前模块的 `下一步` 里，手头主线写完顺手在**同一个会话**里改掉即可。
2. **模块已经做完标为「已完成」，过两天回来改 a（如“修中文乱码”）或改 b（如“加 JSON 导出”）**：
   - 直接选中该老模块 → 点 **`Code`**（状态会自动从 `已完成` 切回 `开发中`，之前的 `mergedCommit` 历史记录会保留）。
   - 点 **「新开改动会话」**，在输入框填一个简短的改动标题（例如：`修中文乱码`），然后点「创建并切换」。
   - 这样模块树依然只有干净的 `结果导出`，而该模块底下的 **「历史会话 / 过往改动」** 会清晰列出 `[Code] 增加 CSV`、`[Code] 修中文乱码`、`[Code] 加 JSON 导出`，互不污染树结构。
3. **只有当它确实是一个“长期存在的独立功能部件”且原会话太长聊不动时**（如 `结果导出` 下的 `字段选择`）：
   - 才点节点行右侧的 **`＋子`** 拆出子模块（子模块自动继承父模块的设计约束与 Worktree 分支）。

## 场景 4：写 A 时想瞄一眼 B，怎么不打断当前聊天？

- **单击树上的任意节点**：**只在侧栏查看它的设计、停在/下一步、关联文件和最新回复摘要，主聊天区纹丝不动**，绝不会把你从 A 会话拉走。
- **确定要切过去干活时**：点击该节点行右侧的 **`↗`** 按钮，或者在详情卡点 **「定位会话」**，主聊天区才会同窗切换过去（且绝不自动发消息）。

## 场景 5：A 和 B 并行开 Worktree——什么时候该开、会不会冲突、怎么合回 `main`？

### 什么时候才值得开 Worktree？
- **不要一上来给所有模块都开 Worktree**；主目录串行写是最省心的常态。
- 满足下面 3 个条件再点 **「创建 Worktree」**：
  1. `项目底座` 已经提交到 `main`；
  2. A 和 B **大概率修改的是不同文件**（边界较清晰；如果边界很糊、都要狂改同一个核心文件，老老实实串行比解冲突快得多）；
  3. 你确实想让 A 和 B 两个 Agent 同时在后台跑 `Code`。
- 开 Worktree 优先开在**父模块**上，下面的子模块会自动继承同一个 Worktree 和分支（树上显示 `WT↑`），避免子模块之间来回合并。

### A 先合进 `main`，B 会受影响吗？B 合并会冲突吗？
1. **A 合并到 `main` 时**：B 在 `.worktrees/<B>` 独立目录里，**完全不受影响**，文件与测试纹丝不动；侧栏只在 B 的 Git 条里显示 **`同步主干 (+1)`** 提醒。
2. **B 准备合并回 `main` 之前（强烈建议先同步再合并）**：
   - 先把 B 的改动在 B 的 Worktree 内提交干净；
   - 如果侧栏提示 `落后主干`，先在 B 点 **「同步主干」**，把 `main`（含 A 的改动）合进 B 的 Worktree：
     - 没改同一块代码 → 0 冲突自动成功；
     - 如果共用文件（如 `App.tsx` 路由、`package.json`）真有小冲突 → 插件会自动 `merge --abort` 保持干净，你可以在 B 的会话里让 Agent 合并主干并解掉冲突、跑通测试；
   - 如有需要，在合并弹窗里点 **「先开独立审查会话」** 做一次终审；
   - 最后点 **「合并回主干」**（默认 **Squash**，1 个模块 1 条干净提交）→ 合并成功后按需点 **「清理 Worktree」** 二次确认删除临时目录和分支，模块节点与 `mergedCommit` 永久留档。

## 场景 6：内置 19 个工程技能如何随阶段自动发挥作用？

`modtree` 已内置 19 个精选工程技能（源自 MIT 协议的 ECC，完整来源见 `THIRD_PARTY_NOTICES.md`），采用 **按阶段自动路由 + 渐进披露**：
- **新开阶段会话时**：冷启动提示词只注入当前阶段对应的 5–8 个技能 ID 与触发条件（Agent 仅在命中场景时才读取对应 `SKILL.md`，不浪费上下文）。
- **切阶段换挡时**：在侧栏把模块从 `Plan → Code` 或 `Code → Review` 切换后，旧会话下一轮发消息时由 `PreInvocation` Hook 自动推送新阶段的推荐技能列表。
- **里程碑收口软引导**：在 `Code` 阶段准备将模块推到 `待检查` 前，建议按 `verification-loop` 跑 6 步验证闭环（构建/类型检查/Lint/测试/安全扫描/Diff 复核），再回写进度或进 `Review`。
- **C++ / ESP32 自动嗅探**：仅当仓库根目录或模块关联文件检测到 `CMakeLists.txt`、`platformio.ini`、`sdkconfig`、`.cpp`/`.hpp` 或固件模块标识时，才会在 `Code`/`Review` 阶段附加 `cpp-coding-standards` 与 `cpp-testing`，对普通项目完全零干扰。
- **主控与跨阶段兜底**：部署发布用 `deployment-patterns`；连续报错陷入循环用 `agent-introspection-debugging`；长会话过阶段节点先回写进度再用 `strategic-compact` 建议 `/compact` 或开新阶段会话。

## 场景 7：原生交互会话（支持 `/grill-me` 弹窗与终端审批）与多阶段并行不打断

1. **为什么推荐「复制开场指令（推荐）」+ 左上角原生 `+` 新建？**
   - Antigravity 宿主将 Sidecar 后台调 `agentapi new-conversation` 创建的会话视作非交互会话，会自动取消 `ask_question`（`/grill-me`）和需要审批的终端弹窗；
   - 点击侧栏 **「复制开场指令（推荐）」**（可填自定义主题，`Plan` 阶段默认勾选附带 `ask_question` 访谈）→ 点左上角原生 **`+` 新建会话** → 粘贴发送：首轮即可完成自绑定、自动命名、返回完整 4 层上下文与阶段技能，并 100% 保留原生弹窗能力。
   - 若你已在某个原生会话里聊上了，点侧栏 **「绑定当前会话」**（可选自定义主题），下一轮发消息时 `PreInvocation` 会自动静默补注完整模块上下文。
2. **编码中途想看 `Plan` 记录，或 `Code` 写完想回 `Plan` 改方案**：
   - 查看其他阶段聊天请直接点会话区上方的 **各阶段直达条（`Plan ↗` / `Code ↗` / `Review ↗`）**，**绝不修改模块阶段**；
   - 多阶段分会话协作时，每个绑定会话遵循自身阶段门禁（`Plan`/`Review` 恒只读，`Code` 恒可写），即使误点顶部阶段切换也会在 `Code` 运行中弹窗拦截；
   - `Plan` 改完方案调用 `modtree_update_module` 更新 `design`（`rev+1`）后，回原 `Code` 会话发下一句话即通过 `PreInvocation` 自动收到最新 `design` + `stop/next`；若大改重来，则直接复制新 `Code` 开场指令开干净会话。
3. **升级插件后的刷新提醒**：
   - 每次运行 `scripts/install.ps1` 升级后，建议在 Antigravity 插件管理页开关一次 `modtree`（或重载窗口），避免旧缓存的 MCP 工具 Schema 过滤掉新版参数（如 `slug`）。
